## 0. 水滴版本实施与验证

### 分工与落地

- 精确锁定 `liquid-gooey@0.2.1`，不使用 `^`。沿用 dnd-kit 输入/圆形命中/自动滚动和 Motion/D3 布局，不引入 GSAP、Canvas 或 WebGL。
- `LiquidDragLayer` portal 到 body；一个全屏 Liquid、最多三个对象：move 水滴和两个 morph 边缘锚点。不复制真实气泡，不改 droppable rect 或 D3 容量。
- favicon 与名称是滤镜外的独立 DOM；原生 mouse/touch 客户端坐标只写 Motion values，避免自动滚动位移重复叠加，无逐帧 React setState。
- `LiquidSession` 管理视觉状态和独立 360ms 清理定时器。成功/返回均不依赖旧 draggable 节点；完成、超时、中断与卸载均释放 pending。
- `onMove` 返回是否真正移动。有效放下立即更新配置、目标分页和 5 秒撤销；目标 tile 保持占位但暂时透明，收尾后显示并聚焦。同分类和其他 no-op 不产生移动或撤销记录。
- 归位期间逐帧测量目标 `.site-icon`，最多等待其挂载 60ms；缺失则走可见目标边缘，否则原地收缩淡出。开始降级后不因迟到节点重新播放；整个收尾上限 360ms。
- 取消时优先跟随仍可见的源图标，否则原地淡出。新 pointerdown/keydown 可中断旧收尾，避免快速重拖/立即撤销被视觉锁阻塞。
- 保留拖动和收尾 click 抑制。撤销按钮另以匹配的 pointerdown/up 处理明确点击，避开已安装 dnd-kit 拖后 50ms 的捕获 click 拦截；键盘 click 仍保留。
- 键盘、减少动态与 SVG 能力缺失使用普通 DragOverlay；成功只显示 450ms 静态落点光圈。减少动态通过 `useMotionPreference` 订阅实时系统变化，拖动中打开也会释放液态层。组件错误边界提供额外装饰层降级。

| blur / contrast / waviness / filterPadding | 10 / 20 / 0 / 40 | 8 / 20 / 0 / 40 |

## 1. 用户的原始需求与实施边界

### 1.1 整体视觉方向

用户此前明确提出：

- “页面的UI和动画需要很有创意 很精致”。
- 不需要大 Banner 和不必要的工作台标题；导航站本质上是工具，分类与网站应该密集一些，减少下滑。
- 网站改为图标加名称平铺，类似 macOS 的 App 页面，支持左右滑动，并有一定毛玻璃效果。
- 背景使用优雅的自然风光图片。
- 将容纳网站图标的框改为气泡，随着容纳的网站数量膨胀。
- 长按图标进入编辑模式，所有图标抖动；点击编辑、点击右上角的叉删除；点击真正的页面空白完成编辑。
- 优先使用成熟第三方能力，非必要不要完全从头实现。

设计原则：**精致，但不能牺牲导航效率、图标密度、搜索焦点和操作反馈。** 项目指南中的 iPhone 产品页完成度是质量参考，不是已实现效果的声明。

### 1.2 水滴需求原话

> “编辑模式下 拖动网站图标无法挪到另一个分类中去 思考技术上能否实现? 如果可以实现 特效上怎么做水滴拖出和拖入的特效? 只分析可行性 不动手 有第三方组件优先用第三方成熟能力”

这条需求的核心是：**网站图标从源分类气泡中像水滴一样分离，拖入另一个分类时呈现液态融入的感受。** 不只是把矩形卡片换成圆角，也不只是给普通拖拽增加阴影。

### 1.3 随后的实施决定

用户随后明确要求：

> “先实现能力 暂不实现特效和动画 开始实施”

因此当前分成两阶段：

1. **先实现可靠的跨分类拖放**：已完成能力版。
2. **之后再做水滴特效**：保留需求和方案，尚未开始实现，需后续明确安排。

“暂不实现动画”指本次跨分类拖放不新增水滴、融合或落下动画；不表示移除之前已有的编辑抖动、气泡尺寸和布局过渡。

## 3. 此前讨论的水滴效果分镜（建议稿）

**整体顺序：提起 → 边缘黏连 → 分离 → 靠近目标 → 融合归位。** 特效仅在操作时出现，不建议所有气泡一直大幅漂浮或持续变形。

### 3.1 提起：图标变成一颗小水滴

- 编辑模式中启动拖动时，图标轻微放大，外面出现半透明的水滴外壳。
- 原位置保留淡占位，让用户知道图标来自哪里，真实排布暂不改变。
- 暂停被拖图标的编辑抖动，避免抖动和拖动叠加。
- 图标位置直接跟随鼠标或手指，弹性主要作用于外壳，不能让图标拖在指针后面。

### 3.2 拖出：源气泡边缘短暂黏连

- 水滴接近源气泡边缘时，边缘沿拖动方向轻微鼓起。
- 气泡与水滴之间形成短的连接细颈，继续拉远时逐渐变细。
- 超过分离阈值后断开，源气泡边缘回弹，水滴独立移动。
- **黏连仅发生在边缘附近，不从气泡中心拉出一条贯穿页面的长丝。**
- 只改变装饰轮廓，不因拉伸就修改真实气泡容量、碰撞区域或网站归属。

### 3.3 靠近目标：明确“可以放进去”

- 有效目标气泡边缘微亮，朝水滴方向轻微凸起；接近时可以出现短暂黏连。
- 视觉上暗示接收，但悬停不更新真实分类数据。
- 无效区域、圆形外部四角不能显示成功接收反馈。
- 装饰性吸引不改变命中规则，不能出现“看上去碰到就被误移走”的情况。

### 3.4 松手：融合、归位与容量变化

- 有效放下时，水滴短暂融入目标气泡，图标过渡到 D3 算出的新位置。
- 源气泡按数量减少收缩，目标按数量增加膨胀；达到尺寸上限后仍使用分页。
- 目标有分页时，显示新图标所在页，不能只播融合动画却让用户找不到图标。
- 图标和名称最后恢复正常清晰显示，不残留液态外壳、重复图标或占位。

### 3.5 取消：回到原位

- 无效放置、同分类放置或取消拖动时，不改变数据。
- 可增加短促的返回/回弹反馈，结束后清理装饰层并恢复编辑状态。
- 返回动画不能导致尾随点击误打开网站、弹出编辑器或退出编辑模式。

## 4. 第三方能力优先的技术思路

下面保留的是此前的推荐分工，不是重新进行组件选型或承诺最终表现。本次未新增依赖。

| 职责 | 复用方案 | 项目需要补充的部分 |
|---|---|---|
| 拖放输入与状态 | 当前 `@dnd-kit/core` | 网站/分类映射、业务落点、动效状态衔接 |
| 顶层拖动预览 | 当前 `DragOverlay` + portal | 包装小水滴外壳，处理放下与取消后的视觉收尾 |
| 气泡尺寸、图标排布 | 当前 `d3-hierarchy` 的 `packSiblings` / `packEnclose` | 保留尺寸上限和分页规则 |
| 伸缩、回弹、归位 | 已有 Motion | 动画节奏、外壳变形和新落点衔接 |
| 液态黏连轮廓 | 原生 SVG 的局部装饰层，待验证 | 凸起、细颈、断开及玻璃材质融合 |

### SVG 液态层的候选做法

此前提出：尝试组合 `feGaussianBlur` 与 `feColorMatrix`，模拟形状靠近时融合、离开时断开的轮廓（gooey/metaball）；配合少量 SVG 路径或形状变形，表现细颈和边缘凸起。

- **内容层与液态装饰层分开**：滤镜只用于液体轮廓，favicon、名称、删除按钮不能一起被模糊。
- 毛玻璃、渐变、阴影和反光继续复用 CSS 质感；液态轮廓如何无缝接上现有玻璃边缘，需要视觉原型验证。
- 效果只覆盖当前源/目标附近，不给整个页面或所有气泡持续加模糊滤镜。
- 这是视觉模拟，不是真实流体。此前未确认存在可以直接完成整套“玻璃气泡跨分类水滴拖放”的成熟一键组件。
- 不建议为这一效果另外引入真实流体、Matter.js 或 WebGL 物理模拟；也不应在未证明现有 Motion 不够用前再增加一套动画库。

## 5. 不应破坏的工程边界

1. **悬停只预览，成功松手才提交。** 源与目标分类一次更新，保留网站 ID、字段、使用次数与原有本地存储格式。不要等动画播放结束才决定移动是否成立。
2. **真实布局保持稳定。** 拖动中不反复搬动真实站点、重算容量；装饰凸起与真实命中区域分离，避免目标随着手指不断跳动。
3. **顶层浮层不被圆形裁切。** 复用当前 portal，后续液态连接也要考虑滚动偏移、分页与视口裁切。
4. **动画不能破坏手势分工。** 保留长按进入编辑、轻点编辑、拖动移动、快速滑动浏览；保留键盘取消和无障碍反馈。
5. **放下后的视觉与数据分别收尾。** 当前拖动结束即清除浮层；后续融合需要单独保留短暂的收尾画面，不能为此重复提交移动或让图标闪失。此项是实施衔接建议，尚未编码。
6. **“最常使用”不是接收分类。** 当前它可作为拖动源；从快捷栏提起时没有实际源气泡边缘，建议不绘制跨屏连向原分类的长丝，具体表现待确认。
7. **取消与撤销保持独立。** 取消不改变配置；成功移动后撤销恢复原分类和原索引。当前撤销窗口为 5 秒，不应被动画重置或阻塞。
8. **性能与降级优先。** 建议减少动态模式关闭拉伸、融合、回弹，仅保留静态目标反馈；移动端必要时降低滤镜复杂度，拖放能力仍须完整可用。

## 6. 后续推进与验收建议

### 推荐顺序

1. 保持已完成的能力版作为基线。
2. 先验证单个源气泡的提起、边缘连接和断开外观。
3. 再接入目标悬停、有效放下融合和无效放下返回。
4. 最后覆盖分页、横向滚动、快捷栏来源、键盘操作和减少动态设置。

每一步独立验收，不要同时重写拖放、布局和视觉层。开发前再核对所用依赖的实际 API；此前讨论中涉及的不同代 dnd-kit API 不能混用。

### 验收要点

- 拖出、黏连、分离、融入能被明显感知，但不过度夸张。
- 指针跟手，图标和名称清晰；没有贯穿页面的长拉丝、重影、残留浮层或布局抖动。
- 装饰轮廓不抢点击、不遮挡删除和撤销，不改变真实落点判断。
- 空分类、满页、尺寸上限、屏幕外分类、取消和连续拖动均正常。
- 搜索焦点、7 个常用站点、点击编辑、删除撤销和空白退出保持原行为。
- 在 `1440×900`、`785×568`、`390×844` 检查视觉与交互；水滴版本还需真实移动 Safari 验证。
- 不预先承诺固定帧率或所有浏览器表现一致；毛玻璃和 SVG 叠加的最终性能尚未实测。

### 尚待确认

水滴外壳透明度与大小、细颈长度、分离距离、回弹强度、各阶段时长及快捷栏来源的特殊效果，均尚未确定。当前鼠标 8px 启动阈值、触摸 220ms 延迟是能力版手势参数，**不是水滴特效参数**。
